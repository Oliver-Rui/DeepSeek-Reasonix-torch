本版修好侧栏排序的两条断路，挡住一个不请自来的项目行，并让版本检查直接读本仓库的发布。

## 修复

- **每一项目录都能拖动，拖到列表最后一位也不再被吞掉**：最后一项目录下面那行是启动时自动打开、并未加入项目列表的文件夹。此前这行连按都按不住（按住只会框选文字），拖到它上面也会被判为"不是目标"而整段忽略——"放到最后"因此没有落点。现在任何项目行都能拖动、也都能命名位置：拖隐式行会把它记进项目列表，落到它上面即落到列表末尾；侧栏（含顶栏 LOGO）也不再能被框选。(8310051, f782abb)
- **项目 / 任务 组头的线跟随落点，而不是固定在下沿**：两段之间只有一个结果（被拖的那段占据目标的位置），所以线画在被拖段落将落的一侧——往上拖画在目标上沿、往下拖画在下沿，松手后就落在那里。(a1e75f0)
- **拖到紧邻行的近端不再"有线条、不落位"**：把一行拖到下一行的上沿（或上一行的下沿）时，落点正是它当前所在的位置——线画在那里、松手却什么都不发生。现在这个边缘会翻到目标的另一侧：向下拖落在目标下面，向上拖落在目标上面，**画出的线就是会落的位置**。项目行与会话行同一条规则，跨行拖动照旧。(dbf1750)
- **会话排序在真实内核上从未生效**：侧栏的会话行与排序接口用的是两套会话枚举——正在对话中的会话（副本只有 lease/inbox 边车，transcript 还没落盘）树里排第一，排序接口却不认它。现在移动与侧栏共用同一份行枚举：进行中的会话可移动（它本就被钉在最上），派发副本不参与，归档分区的步进各自独立。拖拽与 Alt+方向键同一条路径。(d1a798b)
- **"Oliver"（用户主目录）不再冒充项目**：启动根的两条路径都会落到主目录——主机进程继承 shell 的工作目录且选择判定缺主目录守卫；主目录下意外出现的 `.git` 让"最近的 git 根"把它加冕成项目。启动显式拒绝主目录，落到记忆项目或任务工作区。(9e28f11)
- **移除项目这次真的记住**：移除现在写入工作区列表的墓碑（不删任何文件），隐式来源的行不会再在下次启动复活；把文件夹重新添加进来即解除墓碑。任务（auto）工作区永不记墓碑、照常展示。(9e28f11)

## 变更

- **启动时的「正在启动」不再是另一个窗口**：主窗口先以启动页出现，本地服务就绪后在同一窗口载入工作区，启动慢时也不会再额外弹出一个小窗。启动期间关闭这个窗口仍会结束本次启动。(bc41c0f)
- **版本目录改读本仓库的 GitHub 发布**：设置 → 账户 → 版本 现在列出 studio-v 系列，正在运行的版本有标记，有新版本时侧栏脚注会亮起；每行带安装包的直接下载（浏览器保存后自行运行——自更新仍属上游镜像体系）。发布说明即 GitHub 的发布正文。(7b42f43)

## 新增

- 派发工具的说明现在写明"路由者与命名组员"模式：派发时用 `role` 给组员起名（如 组员A：美术 / 组员B：开发），同名组员复用同一会话；组员做完自动回信，途中可用 send_peer_message 向路由者汇报。派发开关打开时，模型可自行搭班子，逐次交付不必请示。(ec6be57)
